## What it does

`triage` 会让项目 Issue tracker 上的 Issues 通过一个小型 **state machine** 的 triage roles 流转：categorise、verify the claim、必要时 grill 成形，并留下 ready-for-agent brief。

它绝不会 blind label。每个 triaged item 都必须有且只有一个 **category** role（`bug` / `enhancement`）和一个 **state** role（`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`），并且它会 *recommend and wait*：先说明自己的 category 和 state 判断及理由，再按你的方向行动。任何东西升到 `ready-for-agent` 前，都先 verify claim：bug 要 reproduce，PR 要 checkout 并 run。

## When to reach for it

你通过输入 `/triage` 并用自然语言描述目标来调用它，agent 不会自行触达它。例如 “Show me anything that needs my attention”、 “let's look at #42”、 “move #42 to ready-for-agent”。

当 Issue tracker 中有 raw、unevaluated reports，需要被 sorted、verified，并转成 agent 或 human 可接手的 work 时使用它。若要把 settled conversation 转成全新 spec，使用 [to-prd](https://aihero.dev/skills-to-prd)；若要把 existing PRD 拆成 Issues，使用 [to-issues](https://aihero.dev/skills-to-issues)。`triage` 是反方向：处理已经落入 tracker 的内容。

## Prerequisites

`triage` 读写 Issue tracker，因此必须先由 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 配置 tracker 和 label mapping。上面的 role names 是 **canonical**；tracker 中实际 label strings 可以不同，而 setup 提供这个 mapping。Config 也决定 external PRs 是否算作 request surface，以及谁算 external。

## A PR is an issue with attached code

当 tracker 把 external pull requests 视为 request surface 时，`triage` 会让它们走过 *同一台* machine：相同 category roles、相同 states、相同 transitions，只是 states 针对 diff 而不是 report 读取。`ready-for-agent` 表示 brief 已附上，agent 应该接手 code 的下一步；`ready-for-human` 表示它已 ready to merge。Discovery 只浮现 external PRs，但显式点名的 PR 总会被 triaged，不管 author 是谁。

## Verify before you brief

让 `triage` 区别于 ad-hoc labelling 的步骤是 verification。它会按 reporter 的 steps reproduce bug，或 checkout PR 并运行 tests，然后报告：confirmed with a code path、failed、或 detail insufficient（这本身就是强 `needs-info` signal）。它还运行两个 codebase checks：**redundancy**（是否已经实现，若是则 `wontfix`）和 **prior rejection**（`.out-of-scope/` 是否已经说 no）。Confirmed verification 会产出强得多的 agent brief；guessing 不会。

## It's working if

- 每个 touched item 最终都有且只有一个 category role 和一个 state role，不是零个，也不是两个冲突 states。
- 它带 reasoning 给出 recommendation 并等待，而不是自行 relabel。
- Bugs 在到达 `ready-for-agent` 前被 reproduced，PRs 在到达前被 run。
- 它发到 tracker 的每条 comment 都以 `> *This was generated by AI during triage.*` disclaimer 开头。

## Where it fits

`triage` 是 Issue tracker 的 **periodic maintenance** pass：当 reports 积压时运行它，保持 queue 已排序，`ready-for-agent` column 可信。它位于 tracker 前端、build chain 上游：它写下的 briefs 是 [tdd](https://aihero.dev/skills-tdd) 后续实现的输入。当 request 需要 sharpen 时，它依赖 [grilling](https://aihero.dev/skills-grilling) 和 [domain-modeling](https://aihero.dev/skills-domain-modeling)，一次一个问题地 grill 成形。它的近邻是 [to-prd](https://aihero.dev/skills-to-prd)，后者从 fresh conversation 填充 tracker，而 `triage` 处理已经在里面的内容。无法确定该用哪个 skill 或 flow 时，由 [ask-matt](https://aihero.dev/skills-ask-matt) 路由。
