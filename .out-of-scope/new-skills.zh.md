# 新 skill proposals 和 contributions

此 repo 不接受新 skill 的 proposals 或 contributions，包括已经附带 ready branch 或 fork 的提交。

## 为什么不在范围内

这份 catalog 是我每天自己使用的一组 skills，并且有意保持精简。每个 skill 都是永久 maintenance surface：它必须与其他 skills、docs pages、`ask-matt` 的 routing map 和 plugin manifest 保持同步。Skills 越短、越少，维护正确的成本越低。

我对自己想法的规则同样适用于这里：如果行为能由现有 skills 组合出来，就不新增 skill。多数 proposals 都是用 grilling、`to-spec`、`to-tickets`、`implement` 等 skills 组成的特定 workflow，这种组合应放在你自己的 prompts 或 skills 中。

非常欢迎你自己发布 skill。skills.sh 让这件事很简单，此 repo 也不需要知道它。

这里只涉及*新* skills。现有 skill 中具体的 failure，仍按 [`SCOPE.zh.md`](../SCOPE.zh.md) 中的门槛判断。
